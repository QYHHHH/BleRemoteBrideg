# Web 配置界面

**默认不在网络上**。板子开机不自动连 Wi-Fi，扫不到任何东西；BLE 主机链路
照常工作。想要配置时**短按一下板上的 BOOT 键**（< 3 秒），板子加入已保存
的 Wi-Fi、计时 30 分钟；时间一到 Wi-Fi 主动关闭，页面打不开。

> 这套"按一下 + 30 分钟"机制替代了原来的密码登录。详细论证见
> [`AUTH.md`](AUTH.md)。

## 打开窗口的三种方式

| 行为 | 怎么触发 |
| --- | --- |
| 打开窗口 | ① 短按板上 BOOT 键；② 串口 `wifi on`；③ 页面里的"再开 30 分钟"按钮 |
| 计时起点 | 板子**拿到 IP 地址那一刻**（不是按下 BOOT 那刻） |
| 计时终点 | 板子主动关 Wi-Fi；HTTP 立即停。BLE 主机端连接不受影响 |
| 续期 | 任意一条打开窗口的方式 |

页面上有个**倒计时面板**（开发板卡片内）和一个**正中大字号提示**（窗口关闭
时显示），任何时候都看得到状态。

## 第一次怎么连

板子从未配过 Wi-Fi 时，`wifi on` 会拒绝（"no Wi-Fi configured yet"）。两条路：

**① 串口**（最快）：

```
首次：串口 wifi join <ssid> <password>   # 凭据持久化
启动：串口 wifi on    或    短按 BOOT     # 打开 30 分钟窗口
查看：串口 wifi status                    # 打印 http://<ip>/ 与剩余秒数
停止：串口 wifi off    或    等 30 分钟   # 关 Wi-Fi、保留所有持久化
```

**② Improv 网页**（免装软件）：板子实现 Improv Wi-Fi 串口协议，可用
[ESPHome Web](https://web.esphome.io/) 直接配：

1. 桌面 Chrome / Edge 打开 https://web.esphome.io/
2. 点 Connect → 选端口（COM3 / CH343）
3. 填 Wi-Fi 与密码 → 跳到板子配置页

要点：
- **必须桌面版 Chrome / Edge / Opera**——国产浏览器与 iOS 不支持 Web Serial
- 页面必须在 HTTPS 或 localhost 下加载，`file://` 被 CORS 挡
- Improv 帧与串口命令**共用同一个 USB 口**，配网时 `status` 等照常可用

## DTR 防护（必须知道）

板子的 USB 串口 **DTR 接到了 BOOT（GPIO9）**。任何软件打开端口时**只要置位
DTR**，固件看来就等于**按住 BOOT**——5 秒后会**清空全部配对与设置**。

> 这跟软件"发不发数据"**无关**，是打开端口那一刻控制线电平的问题。

固件对 Improv 配网页有防护（收到 Improv 帧就不再触发恢复出厂），但**普通
串口软件不受保护**。已实测不置位的：本项目 `scripts/monitor.ps1`
（`DtrEnable = $false`）、MobaXterm 的普通串口。

**通用判据**：打开软件后看日志里有没有 `[BUTTON ] key pressed`，有就说明这个
软件置位了 DTR，赶紧关掉。

## 实时响应（WebSocket 推送）

页面与设备之间是一条 **WebSocket 长连接**——设备一转发按键就把事件推给
页面，**不是页面去问**。同一个连接反向承载配置命令，所以页面既不轮询
也不占用额外的服务槽。

> 为什么不是 SSE：SSE 单向，页面写配置仍需另一条通道，而设备一次只服务一个
> 连接——两条通道会互相阻塞。WebSocket 双向、单连接，正好。
>
> 保活：设备每 10 秒发 ping，30 秒收不到任何数据就主动断开释放服务槽。
> 固件关闭 Wi-Fi modem sleep——按下即亮，代价是 ~50 KB 堆 + 一直占射频。

## 页面能干什么

- **首页**：遥控器 / 主机连接、最近上报电量与自定义映射数量
- **按键映射**：点卡片或遥控器示意图上的按键 → 选**键盘快捷键**或**媒体动作**
  → 保存并回读确认。支持左右修饰键、仅修饰键组合与单键恢复
- **按键实时反馈**：按下遥控器时页面**对应按键立即高亮**（WebSocket 推送）
- **学习模式（槽位 02 / 03）**：CMCC 这类标准 HOGP 遥控器，按下任意键就
  记录原始码（标准 HID usage 自动显示键名），再点卡片绑定动作

页面**完全离线自包含**——无外部字体、脚本、图片请求，也无遥测。

## 安全边界（HTTP / WS 都是明文）

- HTTP 与 WebSocket **都是明文**——这台设备装不下 TLS（mbedtls 会话 16–40 KB，
  双 BLE 链路下只剩 ~30 KB 堆）
- 服务端仍校验 `Origin` / `Sec-Fetch-Site`（POST 写操作）
- 新增 **Host 头白名单**：只接受 IPv4 字面量与 `<name>.local`，否则 403
  —— 这条堵住 DNS rebinding

**所以页面防的是局域网内的误入与好奇，不是网络抓包。请勿把本设备暴露到
公网**（不要在路由器上做端口转发）。

## 堆水位

Wi-Fi 与 BLE 共享射频和内存。开窗期间堆从 ~87 KB 降到约 **30 KB**（最大连续块
~20 KB）。STA 模式够用；AP 模式（`wifi ap on`）还要再吃掉约 38 KB，堆极低时
DHCP 发不出地址（客户端退化成 `169.254.x.x`）。

## 已知行为 / 注意

- `bind` 串口命令与页面绑定同步，`bind list` 列页面里也会显示
- "恢复默认映射"清**全部**自定义绑定（含串口 `bind`），保留 `map` 基础模式
  与蓝牙配对——不等同于恢复出厂
- 窗口期内页面用 WebSocket 实时更新按键状态，窗口关闭时 WebSocket 也断
- 偶发 USB 掉线（`CM_PROB_PHANTOM`）——重插或换线，不是固件问题

完整串口命令见 [`SERIAL-CONSOLE.md`](SERIAL-CONSOLE.md)；认证机制的旧设计
（含改动原因）见 [`AUTH.md`](AUTH.md)。
